# HydroGLM MCP 使用说明

本项目在 Codex 中注册一个本机 MCP 服务，提供 `ask_hydroglm` 工具。提问由工具发送到瀚海 HydroGLM API；Codex 当前模型保持不变。

## 1. 准备

- Linux。
- 已安装 Codex CLI，终端可以运行 `codex`。
- Python 3.10 或更高版本。
- 本项目只使用 Python 标准库，无需安装第三方 Python 包。
- 已从瀚海平台获取 API Key，并确认 Key 绑定到要使用的智能体。

## 2. 安装

从 GitHub 克隆仓库，或下载源码 ZIP 并解压。进入仓库目录后运行：

```bash
bash setup.sh
```

脚本默认配置 HydroGLM，并提示输入 API Key。输入时不会显示字符。脚本会将 Key 保存到用户配置目录，并把本机 `server.py` 注册为 Codex MCP。

使用 HydroGLM-plus：

```bash
bash setup.sh HydroGLM-plus
```

如果 Codex 已有名为 `hydroglm` 的 MCP，脚本会先询问是否替换。选择否会退出，不会覆盖该配置。安装成功后，重启 Codex。

检查注册项：

```bash
codex mcp list
```

Codex CLI 与 IDE 扩展共用 MCP 配置。详见 [OpenAI Docs：MCP 连接 Codex](https://developers.openai.com/learn/docs-mcp)。

## 3. 手动配置

如不使用安装脚本，在仓库目录运行以下命令。默认配置 HydroGLM：

```bash
python3 configure_key.py --agent HydroGLM
codex mcp add hydroglm -- python3 "$PWD/server.py"
codex mcp list
```

使用 HydroGLM-plus 时，将第一条命令改为 `python3 configure_key.py --agent HydroGLM-plus`；MCP 注册命令不变。如换了仓库位置，重新注册时要使用新路径。

## 4. 在 Codex 中提问

例如：

> 请调用 `ask_hydroglm` 查询：水库汛限水位有什么作用？

如果 Codex 没有调用工具，明确写出“请调用 `ask_hydroglm`”。

### 会话续问

工具回答末尾如包含 `HydroGLM session_id: 12345`，继续提问时把编号作为 `session_id` 传入：

```json
{"question":"刚才提到的措施具体是什么？","session_id":12345}
```

在 Codex 对话中可以这样说：“请调用 `ask_hydroglm`，使用 `session_id=12345`，继续回答：刚才提到的措施具体是什么？”该会话由 HydroGLM 服务端管理；不传 `session_id` 就是新请求。

### 可选参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `agent` | string | `HydroGLM` 或 `HydroGLM-plus`，必须与已配置的 Key 对应；默认 `HydroGLM`。 |
| `web_search` | boolean | `true` 时请求启用瀚海侧联网搜索；默认关闭。 |
| `enable_thinking` | boolean | `true` 时请求启用智能体思考模式；默认关闭。 |

`question` 必填，最多 20,000 个 Python 字符。`session_id` 为非负整数。

## 5. Key 的保存位置

默认保存到：

```text
~/.config/hydroglm-mcp/credentials.json
```

密钥目录仅本人可访问，文件仅本人可读写。设置 `XDG_CONFIG_HOME` 后，配置目录改为 `$XDG_CONFIG_HOME/hydroglm-mcp/`。

也可在启动 MCP 的环境中使用环境变量，环境变量优先于文件：

- HydroGLM：`HANHAI_HYDROGLM_API_KEY`
- HydroGLM-plus：`HANHAI_HYDROGLM_PLUS_API_KEY`

不要把 Key 写进命令行参数、仓库、截图或聊天消息。泄露后应在平台撤销并重新生成。

## 6. 测试连接

检查 Key 和 `/models` 接口：

```bash
python3 diagnose.py --agent HydroGLM
```

HTTP 200 只表示 Key 和模型列表接口可用，不代表问答生成正常。

测试实际问答接口：

```bash
python3 probe_chat.py --agent HydroGLM --question '请用一句话说明水库汛限水位的作用'
```

此命令会生成一次回答，可能产生服务用量。使用 HydroGLM-plus 时将 `--agent` 值改为 `HydroGLM-plus`。

## 7. 故障排查

| 现象 | 原因与处理 |
|---|---|
| Codex 找不到 `ask_hydroglm` | 运行 `codex mcp list` 检查注册；确认 MCP 已启用并重启 Codex。 |
| 提示未配置 Key | 对应智能体尚未配置 Key；HydroGLM 运行 `bash setup.sh` 或 `python3 configure_key.py --agent HydroGLM`，HydroGLM-plus 将智能体参数改为 `HydroGLM-plus`。 |
| HTTP 401 | Key 无效、已撤销或未正确保存；重新配置有效 Key。 |
| HTTP 403 | Key 绑定的智能体与调用时选择的 `agent` 不一致。 |
| HTTP 429 | 服务限流；稍后再试。 |
| `/models` 返回 200，但问答返回 504 | 模型列表与生成接口是不同请求；记录时间、状态码、请求编号和错误内容，联系接口提供方。不要反复重发未变化的请求。 |
| 网络连接失败 | 检查本机到 `hanhai-ai.com` 的网络连接和代理设置。 |

MCP 会在上游错误响应含有这些字段时显示 `request-id`、`date` 等诊断信息；不要附带 API Key 提交故障报告。

## 8. 数据边界与已知限制

- 提问内容会发送到 `https://hanhai-ai.com`。不要发送必须留在本机的材料。
- MCP 使用 OpenAI 兼容 Chat Completions 接口，等待响应最长 180 秒。
- 工具返回 HydroGLM 的文本回答，不提供原生函数调用结果，也不维护本机对话记忆。
- 是否启用联网搜索和思考模式由可选参数控制；服务端是否支持及其效果以瀚海接口为准。

## 9. 移除

移除 Codex 注册项：

```bash
codex mcp remove hydroglm
```

如不再使用，在瀚海平台撤销 Key，并删除 `~/.config/hydroglm-mcp/credentials.json`。若配置了 `XDG_CONFIG_HOME`，请删除对应目录下的文件。
